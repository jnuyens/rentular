<objective>
Author the production compose that wires web + api alongside the existing infra services, hardened for a public VPS (loopback binds, no default passwords, secrets via env_file), plus a prod env template.

Purpose: The existing docker-compose.yml publishes MariaDB/Redis on 0.0.0.0 with default passwords — unacceptable on a public box. A dedicated docker-compose.prod.yml keeps the dev compose intact while giving deploy.sh a hardened full-stack file. MariaDB/Redis are published on 127.0.0.1 (loopback) rather than dropped, so the host-shell bootstrap in deploy.sh (Plan 05) can reach MariaDB at 127.0.0.1:3306 while the DB stays off the public interface.
Output: docker-compose.prod.yml, .env.production.example.
</objective>
