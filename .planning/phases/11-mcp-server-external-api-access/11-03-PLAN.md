<objective>
Close the two role gaps RESEARCH Pitfall 2 found: POST /ledger/:leaseId/record-payment and POST /payments/send-reminder currently accept any accepted role (a viewer passes). Harden both to manager+ using the exact gate mark-month-paid already uses, so the MCP write tools record_ledger_payment and send_reminder are manager+ at the API (the source of truth), not only at the tool boundary.

The per-tenant preferred_channel routing already exists in the 19:15 worker (paymentCheckWorker.ts lines 549-575); extract it into one shared function and call it from both places. No new channels, no new settings.

Purpose: MCP-03 requires guarded write tools; CONTEXT locks "writes require manager+" and "send_reminder (channel-aware)". Without the gate, a write-scoped PAT held by a viewer could record payments or spam tenants. Without channel dispatch, the MCP tool would promise a behavior the endpoint does not have.
Output: two hardened handlers, one shared reminderChannel service used by the worker and the manual path, writeGuards / reminderChannel / manualReminder tests green.
</objective>

| API -> external channel senders (SMS provider, WhatsApp bridge) | Tenant phone numbers and reminder text leave the system; sending must only happen on a configured channel with a real number |
