## Component Inventory

This phase introduces one new dashboard page with multiple view states. No new reusable components are created -- all UI is composed from existing Tailwind patterns established in prior phases.

### Page: Import (`apps/web/app/(dashboard)/import/page.tsx`)

The import page is a single-page flow with 5 distinct view states, controlled by the `import_sessions.status` field returned from the API.

#### State 1: Initial (No Session)

Credential entry form. Shown when the user has no active import session.

| Element | Specification |
|---------|---------------|
| Page title | `text-2xl font-semibold`, "Smovin Import" |
| Beta badge | Inline after title. `text-xs font-semibold uppercase` in `rounded-full px-2 py-0.5 bg-[hsl(var(--primary))] text-[hsl(var(--primary-foreground))]`. Text: "Beta" |
| Subtitle | `text-sm text-[hsl(var(--muted-foreground))]` below title |
| Form card | `rounded-lg border border-[hsl(var(--border))] bg-[hsl(var(--background))] p-6` |
| Email input | `w-full rounded-lg border border-[hsl(var(--border))] bg-[hsl(var(--background))] px-3 py-2 text-sm` |
| Password input | Same as email, `type="password"` |
| Info notice | `rounded-lg bg-blue-50 border border-blue-200 p-4 text-sm text-blue-800 flex items-start gap-2` with Info icon. Explains credentials are encrypted and deleted after import. |
| Submit button | `w-full rounded-lg bg-[hsl(var(--primary))] text-[hsl(var(--primary-foreground))] px-4 py-2.5 text-sm font-semibold` |
| Submit button disabled | `opacity-50 cursor-not-allowed` when either field is empty or while submitting |

#### State 2: Discovering (status = "discovering")

Live progress view while the BullMQ discovery worker scrapes Smovin.

| Element | Specification |
|---------|---------------|
| Status badge | `rounded-full px-2 py-0.5 text-xs font-semibold bg-yellow-100 text-yellow-700`. Text: "Discovering..." |
| Progress message | `text-sm` below status badge. Displays `progress.message` from API (e.g., "Discovering property 3 of 12...") |
| Progress bar container | `w-full bg-[hsl(var(--muted))] rounded-full h-2.5 mt-4` |
| Progress bar fill | `bg-[hsl(var(--primary))] h-2.5 rounded-full transition-all duration-300` with width calculated from `progress.current / progress.total * 100%` |
| Step indicator | `text-xs text-[hsl(var(--muted-foreground))] mt-2`. Displays current step name (login, properties, tenants, leases, payments) |
| Log area | `rounded-lg bg-[hsl(var(--muted))] p-4 mt-6 max-h-48 overflow-y-auto font-mono text-xs` showing progress messages as they arrive |

Polling: `refetchInterval: 2000` via react-query while status is "discovering".

#### State 3: Discovered (status = "discovered")

Property selection list. User picks which Smovin properties to import.

| Element | Specification |
|---------|---------------|
| Status badge | `rounded-full px-2 py-0.5 text-xs font-semibold bg-blue-100 text-blue-700`. Text: "Discovery Complete" |
| Summary line | `text-sm mt-2`. "Found {N} properties with {N} tenants and {N} leases." |
| Select all toggle | Checkbox + label at top of list. `text-sm font-medium` |
| Property list | `rounded-lg border border-[hsl(var(--border))] bg-[hsl(var(--background))] overflow-hidden mt-4` |
| Property row | `flex items-center gap-3 px-4 py-3 border-b border-[hsl(var(--border))] hover:bg-[hsl(var(--muted))]/50` |
| Property checkbox | Standard checkbox input, `h-4 w-4 rounded border-[hsl(var(--border))]` |
| Property name | `text-sm font-medium` |
| Property address | `text-xs text-[hsl(var(--muted-foreground))]` below name |
| Nested counts | `text-xs text-[hsl(var(--muted-foreground))]` inline: "{N} tenants, {N} leases, {N} payments" |
| Duplicate indicator | If property matches existing Rentular data: `text-xs text-[hsl(var(--muted-foreground))] italic`. Text: "Already exists -- will be skipped" |
| Import button | `rounded-lg bg-[hsl(var(--primary))] text-[hsl(var(--primary-foreground))] px-4 py-2.5 text-sm font-semibold mt-4`. Disabled if no properties selected. |
| Cancel button | `rounded-lg border border-[hsl(var(--border))] bg-[hsl(var(--background))] px-4 py-2.5 text-sm font-medium` next to import button |

#### State 4: Importing (status = "importing")

Same layout as State 2 (Discovering) but with import-specific messaging.

| Element | Specification |
|---------|---------------|
| Status badge | `bg-yellow-100 text-yellow-700`. Text: "Importing..." |
| Progress message | "Importing property 3 of 8..." |
| Progress bar | Same specification as State 2 |

Polling: `refetchInterval: 2000` via react-query while status is "importing".

#### State 5: Completed (status = "completed")

Import results summary.

| Element | Specification |
|---------|---------------|
| Status badge | `bg-green-100 text-green-700`. Text: "Import Complete" |
| Results grid | 2x2 grid of count cards, `grid grid-cols-2 gap-4 mt-4` |
| Count card | `rounded-lg border border-[hsl(var(--border))] bg-[hsl(var(--background))] p-4 text-center` |
| Count number | `text-2xl font-semibold` |
| Count label | `text-xs text-[hsl(var(--muted-foreground))] mt-1` (Properties, Tenants, Leases, Payments) |
| Skipped count | If any duplicates were skipped: `text-sm text-[hsl(var(--muted-foreground))] mt-4`. "{N} properties skipped (already existed)" |
| Start new import button | `rounded-lg border border-[hsl(var(--border))] bg-[hsl(var(--background))] px-4 py-2.5 text-sm font-medium mt-6` |

#### State 6: Failed (status = "failed")

Error display with retry option.

| Element | Specification |
|---------|---------------|
| Error alert | `rounded-lg bg-red-50 border border-red-200 p-4 text-sm text-red-800 flex items-start gap-2` with AlertCircle icon |
| Error message | `text-sm` inside alert. Displays `errorMessage` from API |
| Retry button | `rounded-lg bg-[hsl(var(--primary))] text-[hsl(var(--primary-foreground))] px-4 py-2.5 text-sm font-semibold mt-4`. Restarts discovery with stored credentials. |
| Delete credentials button | `rounded-lg border border-[hsl(var(--destructive))] text-[hsl(var(--destructive))] px-4 py-2.5 text-sm font-medium` next to retry button |

## Interaction Contracts

### Polling Behavior

| Trigger | Interval | Stop Condition |
|---------|----------|----------------|
| Status = "discovering" | 2000ms | Status changes to "discovered" or "failed" |
| Status = "importing" | 2000ms | Status changes to "completed" or "failed" |
| Status = "pending", "discovered", "completed" | false (no polling) | N/A |

Implementation: `@tanstack/react-query` `refetchInterval` callback, matching existing pattern in RESEARCH.md.

### Form Validation

| Field | Validation | Error Display |
|-------|------------|---------------|
| Smovin email | Required, basic email format | Inline below input, `text-xs text-[hsl(var(--destructive))]` |
| Smovin password | Required, minimum 1 character | Inline below input, same style |

Client-side only. Server-side validation via Zod on the API route.

### Destructive Actions

| Action | Trigger | Confirmation |
|--------|---------|--------------|
| Delete credentials | Click "Delete Credentials" button | Browser `window.confirm()` with `import.deleteConfirmation` text |
| Cancel discovery | Not supported -- once started, discovery runs to completion |
| Start new import | Click "Start New Import" after completion | No confirmation needed (non-destructive) |

### Navigation

The import page is accessible via a new sidebar nav item in the dashboard layout.

| Property | Value |
|----------|-------|
| Nav key | `"import"` |
| Nav href | `"/import"` |
| Nav icon | `Import` from lucide-react (or `Download` if Import unavailable) |
| Nav position | After "settings", before sign-out area |
| Visibility | Owner only (same restriction as settings) |

Add to `NAV_VISIBILITY` in dashboard layout:
```
import: ["co_owner", "manager", "accountant", "viewer"]  // owner only
```

## Accessibility Contracts

| Requirement | Implementation |
|-------------|----------------|
| Form labels | All inputs have associated `<label>` elements with `htmlFor` |
| Progress bar | `role="progressbar"` with `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"` |
| Status announcements | `aria-live="polite"` on the status/progress region so screen readers announce updates |
| Checkbox list | Standard `<input type="checkbox">` with associated labels |
| Error messages | `role="alert"` on error alert containers |
| Button states | `disabled` attribute + `aria-disabled="true"` on disabled buttons |
| Password visibility | `type="password"` only (no show/hide toggle for Smovin credentials -- security-first approach) |

## Responsive Behavior

This phase does not implement responsive/mobile design (deferred to Phase 7 UI-03). The import page follows the existing desktop-only dashboard layout pattern (`flex h-screen` with fixed 256px sidebar).

The import page content uses max-width for readability:
- Form card: `max-w-lg` (512px)
- Progress display: `max-w-lg`
- Property selection list: `max-w-2xl` (672px)
- Results grid: `max-w-lg`
