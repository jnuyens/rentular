**Endpoint 1: POST / (submit credentials)**

- Validates request body with Zod: `{ email: z.string().email(), password: z.string().min(1) }`
- Gets userId via `getRequiredUserId(c)`
- Encrypts email using `encrypt(email)` -- stores encrypted, iv, tag in separate columns
- Encrypts password using `encrypt(password)` -- stores encrypted, iv, tag in separate columns
- Inserts new row into importSessions with status "pending", generated UUID id
- Returns `{ data: { sessionId: id, status: "pending" } }` with 201 status
- Per D-04: credentials are encrypted using existing AES-256-GCM encryption.ts

**Endpoint 2: GET /status/:sessionId (poll status)**

- Gets userId via `getRequiredUserId(c)`
- Queries importSessions where id = sessionId AND userId = userId
- Returns `{ data: { id, status, progress, discoveredData, selectedProperties, importedCounts, errorMessage, createdAt, updatedAt } }`
- Does NOT return credential columns (never expose encrypted credentials to frontend)
- Returns 404 if session not found or belongs to different user

**Endpoint 3: POST /start-discovery/:sessionId (kick off scraping)**

- Gets userId via `getRequiredUserId(c)`
- Queries session, verifies status is "pending" or "failed" (retry case per D-05)
- Updates session status to "discovering", clears errorMessage
- Adds job to importDiscoveryQueue: `importDiscoveryQueue.add("discover", { sessionId }, { jobId: "discovery-" + sessionId })`
- Stores discoveryJobId on the session
- Returns `{ data: { sessionId, status: "discovering", jobId } }`
- Returns 400 if session status is not "pending" or "failed"

**Endpoint 4: POST /start-import/:sessionId (kick off import of selected properties)**

- Gets userId via `getRequiredUserId(c)`
- Validates body: `{ selectedProperties: z.array(z.number()) }` (array of indices into discoveredData)
- Queries session, verifies status is "discovered"
- Updates session: status = "importing", selectedProperties = body.selectedProperties
- Imports `importWriteQueue` from `../jobs/importWriteWorker` (will exist after Plan 03)
- Adds job to importWriteQueue: `importWriteQueue.add("import", { sessionId }, { jobId: "import-" + sessionId })`
- Stores importJobId on the session
- Returns `{ data: { sessionId, status: "importing", jobId } }`
- Returns 400 if session status is not "discovered"

NOTE: The importWriteQueue import will fail until Plan 03 creates the file. The executor should add a conditional import or comment noting the dependency. A practical approach: create a placeholder `importWriteQueue` export at the bottom of the routes file that will be replaced when Plan 03 completes, OR use dynamic import:
```typescript
const { importWriteQueue } = await import("../jobs/importWriteWorker");
```

**Endpoint 5: DELETE /credentials/:sessionId (delete stored credentials per D-05)**

- Gets userId via `getRequiredUserId(c)`
- Queries session, verifies userId matches
- Updates session: sets all 6 credential columns to null
- Returns `{ data: { sessionId, credentialsDeleted: true } }`
- Returns 404 if not found

**Endpoint 6: GET /latest (get user's most recent import session)**

- Gets userId via `getRequiredUserId(c)`
- Queries importSessions where userId = userId, ordered by createdAt DESC, limit 1
- Returns `{ data: session }` (same fields as status endpoint, no credentials) or `{ data: null }` if none

All endpoints use try-catch with `console.error("[Import] ...")` logging pattern and return 500 on unexpected errors.

**Part A: Create `apps/api/src/jobs/importDiscoveryWorker.ts`**

Follow the emailQueueWorker.ts pattern. This worker:

1. Receives a job with `{ sessionId: string }`
2. Loads the import session from DB
3. Decrypts credentials using `decrypt()` from encryption.ts
4. Launches stealth browser via `createStealthBrowser()` from smovinScraper.ts
5. Logs into Smovin via `loginToSmovin()`
6. Scrapes properties list, then for each property scrapes detail pages for tenants, leases, payments
7. Updates session progress throughout via `db.update(importSessions).set({ progress: {...} })`
8. On success: stores discoveredData JSON, sets status to "discovered"
9. On failure: sets status to "failed", stores errorMessage
10. Always closes browser in `finally` block

```typescript
import { Worker, Queue } from "bullmq";
import { getDb, importSessions } from "@rentular/db";
import { eq } from "drizzle-orm";
import { decrypt } from "../lib/encryption";
import { createStealthBrowser, loginToSmovin, randomDelay } from "../services/smovinScraper";

const QUEUE_NAME = "import-discovery";

const connection = {
  host: process.env.REDIS_HOST || "localhost",
  port: Number(process.env.REDIS_PORT) || 6379,
  maxRetriesPerRequest: null,
};

export const importDiscoveryQueue = new Queue(QUEUE_NAME, {
  connection,
  defaultJobOptions: {
    attempts: 2,
    backoff: { type: "exponential", delay: 10000 },
    removeOnComplete: { count: 50 },
    removeOnFail: { count: 50 },
    timeout: 1800000, // 30 minutes
  },
});
```

The worker processor function should:

a) Load session from DB, decrypt credentials:
```typescript
const db = getDb();
const [session] = await db.select().from(importSessions).where(eq(importSessions.id, sessionId)).limit(1);
if (!session) throw new Error("Import session not found");

const email = decrypt(session.credentialEmail!, session.credentialEmailIv!, session.credentialEmailTag!);
const password = decrypt(session.credentialPassword!, session.credentialPasswordIv!, session.credentialPasswordTag!);
```

b) Update progress helper function:
```typescript
async function updateProgress(step: string, message: string, current = 0, total = 0) {
  const progressData = { step, message, current, total };
  await db.update(importSessions).set({ progress: progressData, updatedAt: new Date() }).where(eq(importSessions.id, sessionId));
  console.log(`[ImportDiscovery] ${message}`);
}
```

c) Launch browser, login, scrape:
- Use `createStealthBrowser()` to get browser + context
- Create new page from context
- Call `loginToSmovin(page, email, password)`
- If login fails: update session status to "failed" with appropriate error message
- If login succeeds: navigate to properties/patrimony page
- Scrape property list: for each property link, navigate to detail page, extract name, address, type
- For each property: navigate to its contracts/leases section, extract lease details (start date, end date, rent amount, charges)
- For each lease: extract associated tenants (name, email, phone)
- For each property: navigate to payments/management section if accessible, extract payment history
- After each property scraped: call `updateProgress("properties", "Discovering property X of Y...", currentIndex, totalCount)`
- Store all discovered data as typed JSON:

```typescript
interface SmovinDiscoveredProperty {
  name: string;
  address: string;
  type: string;
  tenants: Array<{ firstName: string; lastName: string; email?: string; phone?: string }>;
  leases: Array<{ startDate: string; endDate?: string; monthlyRent: string; charges?: string; type?: string }>;
  payments: Array<{ date: string; amount: string; status: string; description?: string }>;
}
```

d) On completion, update session:
```typescript
await db.update(importSessions).set({
  status: "discovered",
  discoveredData: discoveredProperties,
  progress: { step: "complete", message: "Discovery complete", current: totalCount, total: totalCount },
  updatedAt: new Date(),
}).where(eq(importSessions.id, sessionId));
```

e) On failure, update session:
```typescript
await db.update(importSessions).set({
  status: "failed",
  errorMessage: errorMsg,
  updatedAt: new Date(),
}).where(eq(importSessions.id, sessionId));
```

f) Always close browser in `finally` block.

g) Worker event handlers:
```typescript
worker.on("failed", (job, err) => {
  console.error(`[ImportDiscovery] Job ${job?.id} failed:`, err.message);
});
worker.on("completed", (job) => {
  console.log(`[ImportDiscovery] Job ${job.id} completed`);
});
```

Set concurrency to 1 (one browser at a time per D-03 resource management).

**IMPORTANT NOTE on selectors:** The exact DOM selectors for Smovin pages are unknown until the spike test reveals the page structure. The executor should reference the spike test results from Plan 01's SUMMARY to determine actual selectors. Use resilient selector strategies:
- Prefer `text=` selectors for labels
- Prefer `role=` selectors for semantic elements
- Use `page.$$eval("table tr", ...)` for tabular data
- Wrap each scraping section in try-catch so partial failures don't lose all data
