# Phase 4 -- UI Design Contract

> Visual and interaction contract for the Communications dashboard page and SMTP Settings section. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom Tailwind + CSS variables) |
| Preset | not applicable |
| Component library | none -- hand-rolled components following existing project patterns |
| Icon library | Lucide React 0.468.x |
| Font | System font stack (no custom font declared in tailwind.config.ts) |

**Note:** This project does not use shadcn. All components follow the existing pattern of inline Tailwind classes with HSL CSS custom properties (`hsl(var(--background))`, `hsl(var(--primary))`, etc.). Phase 4 continues this pattern.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (gap-1), inline padding (px-1, py-0.5) |
| sm | 8px | Compact element spacing (gap-2, p-2), tab gaps |
| md | 16px | Default element spacing (gap-4, p-4), sidebar nav item padding |
| lg | 24px | Section padding (p-6), card internal padding |
| xl | 32px | Main content padding (p-8), page-level gaps (mb-8) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:

| Value | Tailwind | Justification |
|-------|----------|---------------|
| 10px | `py-2.5` | Matches established project-wide pattern used in layout.tsx sidebar nav items, all dashboard buttons, select dropdowns, and input fields. Present in 20+ instances across the codebase. Changing to a multiple of 4 would break visual consistency with existing pages. |

**Source:** Extracted from existing dashboard layout.tsx and settings/page.tsx patterns. Main content uses `p-8`, cards use `p-6`, nav items use `px-3 py-2.5`, buttons use `px-4 py-2.5`.

## Typography

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (normal) | 1.5 | `text-sm` |
| Label | 14px | 600 (semibold) | 1.5 | `text-sm font-semibold` |
| Subheading | 18px | 600 (semibold) | 1.3 | `text-lg font-semibold` |
| Heading | 24px | 600 (semibold) | 1.2 | `text-2xl font-semibold` |

**Weights used:** 2 -- normal (400) for body/table text, semibold (600) for labels, subheadings, and headings.

**Source:** Consolidated from existing patterns. The codebase uses `font-medium` (500) and `font-bold` (700) in some places, but this phase standardizes on 400 + 600 to stay within the 2-weight limit. Existing page patterns use `text-lg font-semibold` for card headings and `text-sm` for body, which already align.

## Component Inventory

### 1. Communications Page (`/communications`)

**Page Header**
- Title: `h1.text-2xl.font-semibold` -- "Communications"
- Subtitle: `p.text-sm.text-[hsl(var(--muted-foreground))]` -- "View all sent emails and SMS messages"
- No primary CTA button in the header (this is a read-only log)

**Filter Bar**
- Container: `div.flex.gap-2.items-center.mb-6`
- Property filter: `<select>` dropdown with `rounded-lg border border-[hsl(var(--border))] bg-[hsl(var(--background))] px-3 py-2 text-sm`
- Tenant filter: same styling as property filter
- Type filter: same styling, options map to `communications.type` enum values with human-readable labels
- All filters default to "All" (no filter applied)

**Communications Table**
- Container: `div.rounded-lg.border.border-[hsl(var(--border))].bg-[hsl(var(--background))].overflow-hidden`
- Table header row: `bg-[hsl(var(--muted))]` with `text-xs font-semibold text-[hsl(var(--muted-foreground))] uppercase tracking-wider`
- Columns: Type | Channel | Recipient | Subject | Date | Status
- Column widths: Type 15% | Channel 8% | Recipient 20% | Subject 30% | Date 15% | Status 12%

**Table Row (collapsed)**
- Row: `border-b border-[hsl(var(--border))] hover:bg-[hsl(var(--muted))]/50 cursor-pointer transition-colors`
- Type cell: human-readable label (e.g., "Friendly reminder", "Indexation notification")
- Channel cell: badge with icon -- `Mail` icon for email, `MessageSquare` icon for SMS
- Recipient cell: `recipientName` with `recipientEmail` or `recipientPhone` in `text-xs text-[hsl(var(--muted-foreground))]` below
- Subject cell: truncated with `truncate` class, max one line
- Date cell: formatted relative or absolute date in `text-sm`
- Status cell: status badge (see Status Badge Colors above)

**Table Row (expanded)**
- Expanded area: `bg-[hsl(var(--muted))]/30 px-6 py-4 border-b border-[hsl(var(--border))]`
- Shows: full subject line, full body content in `whitespace-pre-wrap text-sm`, error message if status is failed
- Body rendered in a `div.rounded-lg.bg-[hsl(var(--background))].p-4.text-sm.whitespace-pre-wrap.font-mono.max-h-64.overflow-y-auto`
- Error message (if failed): `div.mt-2.text-sm.text-red-600` with `AlertCircle` icon

**Empty State**
- Container: centered in table area, `py-16 text-center`
- Icon: `Mail` from Lucide, `h-12 w-12 text-[hsl(var(--muted-foreground))]` centered
- Heading: "No communications sent yet"
- Body: "Emails and SMS messages will appear here once payment reminders or notifications are sent."

**Pagination**
- Not required for launch. Load up to 50 most recent communications. If needed later, add "Load more" button at bottom.

### 2. Settings Page -- Email Settings Tab

**New Tab**
- Add "Email Settings" tab to existing tab bar after "bank-accounts" and before "general"
- Tab key: `"email-settings"`
- Tab label: i18n key `settings.emailSettings`
- Active state: same `bg-[hsl(var(--primary))] text-[hsl(var(--primary-foreground))]` pattern

**SMTP Configuration Card**
- Container: `div.rounded-lg.border.border-[hsl(var(--border))].bg-[hsl(var(--background))].p-6`
- Card heading: `h2.text-lg.font-semibold` -- "Custom SMTP Server"
- Card description: `p.text-sm.text-[hsl(var(--muted-foreground))]` -- "Send emails from your own domain instead of the Rentular platform. Leave blank to use the default Rentular email sender."
- Form fields (vertical stack, `space-y-4`):

| Field | Type | Placeholder | Validation |
|-------|------|-------------|------------|
| SMTP Host | text input | `smtp.example.com` | required if any field is filled |
| SMTP Port | number input | `587` | 25, 465, 587, 2525 |
| Username | text input | `user@example.com` | required if host is filled |
| Password | password input | (masked) | required if host is filled |
| From Address | email input | `noreply@yourdomain.com` | valid email required |
| From Name | text input | `Your Company Name` | optional |

- Input styling: `w-full rounded-lg border border-[hsl(var(--border))] bg-[hsl(var(--background))] px-3 py-2 text-sm focus:outline-none focus:ring-2 focus:ring-[hsl(var(--primary))]/50`
- Label styling: `block text-sm font-semibold mb-1`

**Verification Status Indicator**
- When SMTP settings are saved and verified: `div.flex.items-center.gap-2.text-sm.text-green-600` with `CheckCircle2` icon -- "SMTP connection verified"
- When SMTP settings are saved but not verified: `div.flex.items-center.gap-2.text-sm.text-yellow-600` with `AlertCircle` icon -- "Not yet verified"
- When verification failed: `div.flex.items-center.gap-2.text-sm.text-red-600` with `XCircle` icon -- "Verification failed: {error}"

**Action Buttons**
- "Send test email" button: `rounded-lg border border-[hsl(var(--primary))] text-[hsl(var(--primary))] px-4 py-2.5 text-sm font-semibold hover:bg-[hsl(var(--primary))]/10 transition-colors` (outlined style, not filled -- secondary action)
- Loading state: button text changes to "Sending..." with disabled state, `opacity-50 cursor-not-allowed`
- Success feedback: inline text below button -- "Test email sent to {email}" in `text-sm text-green-600`
- Failure feedback: inline text below button -- "Failed: {error}" in `text-sm text-red-600`
- "Save settings" button and "Reset to defaults" button use existing settings page pattern: page-level save/reset at the top of the settings area

**SMS Consent Notice**
- In the existing "follow-up" tab, add an info banner above the SMS toggle:
- Container: `div.flex.items-start.gap-3.rounded-lg.bg-blue-50.border.border-blue-200.p-4.text-sm.text-blue-800`
- Icon: `Info` from Lucide, `h-5 w-5 flex-shrink-0 mt-0.5`
- Text: "SMS consent is your responsibility as a landlord. Ensure you have obtained explicit consent from tenants before enabling SMS reminders. Rentular does not manage tenant opt-in/opt-out."

## Interaction Patterns

### Expandable Table Rows
- Click anywhere on a table row to toggle expansion
- Visual indicator: `ChevronDown` icon on the right side of each row, rotates 180deg when expanded (`transition-transform duration-200`)
- Only one row expanded at a time (accordion behavior) -- expanding a new row collapses the previously expanded one
- Expanded content slides in with no animation (instant render, no CSS transitions on height)

### Filter Dropdowns
- Native `<select>` elements (no custom dropdown components)
- Changing any filter immediately re-fetches the communications list
- Filters persist in component state only (no URL params for launch)

### SMTP Form
- All fields are optional as a group (landlord can clear all fields to revert to platform default)
- If any field is filled, host/port/username/password/fromAddress all become required (client-side validation)
- Password field has eye-toggle to show/hide (use existing `Eye`/`EyeOff` pattern from payments page)
- "Send test email" button is disabled until all required fields are filled
- "Send test email" does NOT save settings -- it tests with the current form values. Landlord must click "Save settings" separately.

### Loading States
- Communications page: skeleton placeholder -- 5 rows of `animate-pulse bg-[hsl(var(--muted))] h-12 rounded` while loading
- SMTP settings: button loading spinner pattern (text swap to "Sending..." + disabled)

### Error States
- API fetch failure on communications page: `div.rounded-lg.bg-red-50.border.border-red-200.p-4.text-sm.text-red-800` with `AlertCircle` icon and text "Failed to load communications. Please try again."
- SMTP test failure: inline error text below the button (no modal, no toast)

## Accessibility Notes

- Table rows use `role="button"` and `tabindex="0"` with `onKeyDown` handler for Enter/Space to toggle expansion
- Filter `<select>` elements use native HTML for built-in screen reader support
- Status badges include the status text (not icon-only)
- SMTP password toggle button has `aria-label="Show password"` / `aria-label="Hide password"`
- Expanded row content is within a `div` with `aria-expanded="true"` on the parent row
