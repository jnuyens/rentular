# Phase 7 — UI Design Contract

> Visual and interaction contract for UI Polish, Onboarding & Launch Readiness. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (via `shadcn@2.3.0`, pinned for Tailwind v3 compatibility) |
| Preset | Default style, Blue base color, CSS variables enabled |


Plus the `sonner` toast wrapper.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding (py-0.5, px-1) |
| sm | 8px | Compact element spacing, gap-2, py-2 |
| md | 16px | Default element spacing, px-4, py-4, form field gaps |
| lg | 24px | Section padding, px-6, py-6, card internal padding |
| xl | 32px | Layout gaps, p-8 (main content area), mb-8 page headers |
| 2xl | 48px | Major section breaks, marketing page section spacing |
| 3xl | 64px | Page-level spacing, py-16 (marketing hero/section padding) |

Exceptions:
- Mobile top bar height: 56px (h-14) -- standard mobile app bar
- Touch targets on mobile: minimum 44px (11 Tailwind units / p-2.5 + icon) per WCAG 2.1 AA
- Desktop sidebar width: 256px (w-64) -- existing value, unchanged
- Marketing sticky nav height: 64px (h-16) -- matching dashboard sidebar header

Source: Existing dashboard layout uses `p-8` main content, `px-6` sidebar header, `px-3 py-4` nav items.

## Interaction Contracts

### Facebook-Style Auth Routing (D-02)

| Condition | Behavior |
|-----------|----------|
| User has valid session | `redirect("/properties")` from server component |
| User has no session | Render marketing landing page |
| User at `/login` with session | Redirect to `/properties` |

Implementation: `app/page.tsx` becomes server component calling `auth()`. Marketing page content is a separate client component rendered conditionally.

### Onboarding Redirect (D-14)

| Condition | Behavior |
|-----------|----------|
| Authenticated + `onboardingComplete === false` + not on `/onboarding` | Redirect to `/onboarding` |
| Authenticated + `onboardingComplete === true` | Pass through to dashboard |
| Authenticated + on `/onboarding` | Pass through (no redirect loop) |
| Unauthenticated | Redirect to `/login` (existing behavior) |

Middleware order: (1) public page check, (2) auth check, (3) onboarding check.

`onboardingComplete` is added to the NextAuth session callback/JWT to avoid per-request API calls.

### Mobile Drawer

| Trigger | Behavior |
|---------|----------|
| Tap hamburger icon | Sheet slides in from left, overlay dims content |
| Tap overlay | Sheet closes |
| Tap X button | Sheet closes |
| Tap nav item | Navigate + Sheet closes |
| Viewport >= 768px | Sheet hidden, desktop sidebar visible |

### Form Validation (Onboarding)

| Step | Required Fields | Validation |
|------|----------------|------------|
| 1. Property | address, city, postalCode, type, region | All required, postalCode 4 digits |
| 2. Tenant | name, email, language | name required, email format, language from enum |
| 3. Lease | propertyId, tenantId, startDate, monthlyRent, type | All required, monthlyRent > 0 |
| 4. Payment | Depends on collection method | GoCardless: mandate flow, Manual: no validation |

Client-side validation with inline error messages (`text-xs text-destructive`) below each field. Server-side validation via existing API Zod schemas.

### Destructive Actions

| Action | Trigger | Confirmation Method |
|--------|---------|-------------------|
| Delete property | Click delete button on property row/card | shadcn AlertDialog: "Are you sure?" with delete/cancel buttons |
| Delete tenant | Click delete button on tenant row/card | shadcn AlertDialog |
| Delete lease | Click delete button on lease row/card | shadcn AlertDialog |
| Cancel payment | Click cancel button on payment | shadcn AlertDialog |
| Delete import credentials | Click "Delete Credentials" | shadcn AlertDialog |
| Skip onboarding | Click "Skip setup" link | No confirmation (non-destructive, can return) |

All destructive confirmations use shadcn AlertDialog instead of `window.confirm()`. This is a migration from Phase 6's browser confirm pattern.

### Toast Behavior

| Event | Toast Type | Duration |
|-------|-----------|----------|
| Successful save/create/update | `toast.success()` | 4000ms |
| Successful delete | `toast.success()` | 4000ms |
| API error | `toast.error()` | 6000ms (longer for error reading) |
| Network timeout | `toast.error()` | 8000ms |
| Long operation start | `toast.promise()` | Until resolved |
