- Requires query param `propertyId`
- Get userId via `getRequiredUserId(c)`

- Query `propertyManagers` where `eq(propertyManagers.propertyId, propertyId)`
- Left join with `users` table to get name and email for each manager
- Return `{ data: [...] }` with each entry having `id, propertyId, userId, role, invitedBy, invitedAt, acceptedAt, invitationEmail, user: { name, email }`

**GET `/my-properties` -- List all properties user has access to:**
- Get userId via `getRequiredUserId(c)`
- Query propertyManagers joined with properties where `eq(propertyManagers.userId, userId)` and `isNotNull(propertyManagers.acceptedAt)`
- Return `{ data: [...] }` with each entry having property fields plus `role`

**POST `/invite` -- Invite a user to manage a property:**
- Zod validation: `{ propertyId: z.string().uuid(), email: z.string().email(), role: z.enum(["co_owner", "manager", "accountant", "viewer"]) }`
- Get userId via `getRequiredUserId(c)`
- Check user has co_owner+ access via `getUserPropertyRole(userId, propertyId)` -- return 403 if insufficient
- Prevent inviting yourself (compare email with caller's email from users table)
- Look up invitee by email in users table
- **D-12 overwrite logic:** If invitee exists as user AND already has a record in propertyManagers for this property, update their role via `db.update(propertyManagers).set({ role, invitedBy: userId, invitedAt: new Date() })`. Send role change email. Return `{ message: "Role updated" }`
- **New invitation:** Generate token via `crypto.randomUUID()`. Calculate expiresAt as `new Date(Date.now() + 90 * 24 * 60 * 60 * 1000)` (D-03: 90 days)
- If invitee exists as user: insert with `userId: existingUser.id, acceptedAt: null`
- If invitee does NOT exist: insert with `userId: null, invitationEmail: email, acceptedAt: null` (D-01: non-users can be invited)
- Set `invitationToken: token, invitationExpiresAt: expiresAt, invitationEmail: email`
- Build accept URL: `` `${process.env.WEB_URL || "http://localhost:3000"}/invite/accept?token=${token}` ``
- Look up property name for the email template
- Look up inviter name from users table
- Send invitation email via `queueEmail`:
  - `to: email`
  - `subject: "${inviterName} invited you to manage a property on Rentular"`
  - `html:` a simple HTML email body with heading "You have been invited", body text "{inviterName} has invited you to manage {propertyName} as {roleName}.", a CTA link "Accept Invitation" pointing to the accept URL, and footer "This invitation expires in 90 days. If you did not expect this invitation, you can safely ignore this email."
  - Pass `meta: { propertyId, type: "invitation" }` and ownerId (the property owner's ID from properties table)
- Return `c.json({ message: "Invitation sent", id }, 201)`

**POST `/accept` -- Accept an invitation by token:**
- Expects JSON body: `{ token: z.string().uuid() }` validated via Zod
- Get userId via `getRequiredUserId(c)` (user must be logged in)
- Look up the invitation by `eq(propertyManagers.invitationToken, token)`
- If not found: return 404 `{ error: "Invitation not found" }`
- If `invitationExpiresAt < new Date()`: return 410 `{ error: "Invitation has expired" }`
- If `acceptedAt` is already set: return 409 `{ error: "Invitation already accepted" }`
- Update the record: set `userId: userId, acceptedAt: new Date(), invitationToken: null` (clear token after use)
- **D-01 auto-link pending invitations:** After a successful accept, also check for any OTHER pending invitations where `invitationEmail` matches the current user's email AND `userId IS NULL`. For each such record, update it to set `userId: userId` (link the user to their pending invitations so they appear in their invitation list). This handles the case where a non-user was invited, registered, and now their pending invitations across different properties get linked to their new account. Do NOT auto-accept these other invitations -- just link the userId so the user can find and accept them individually.

  Implementation:
  ```typescript
  // After successful accept, link any other pending invitations for this user's email
  const currentUser = await db.select({ email: users.email }).from(users).where(eq(users.id, userId));
  if (currentUser[0]?.email) {
    await db.update(propertyManagers)
      .set({ userId: userId })
      .where(
        and(
          eq(propertyManagers.invitationEmail, currentUser[0].email),
          isNull(propertyManagers.userId),
          isNull(propertyManagers.acceptedAt)
        )
      );
  }
  ```

- Return `{ message: "Invitation accepted", propertyId: record.propertyId, role: record.role }`

**POST `/decline` -- Decline an invitation by token:**
- Expects JSON body: `{ token: z.string().uuid() }`
- Look up invitation by token (same as accept)
- If not found or expired: same errors as accept
- Delete the record: `db.delete(propertyManagers).where(eq(propertyManagers.id, record.id))`
- Return `{ message: "Invitation declined" }`

**PATCH `/:id` -- Update a manager's role:**
- Zod validation: `{ role: z.enum(["co_owner", "manager", "accountant", "viewer"]) }`
- Get userId via `getRequiredUserId(c)`, get manager record by `c.req.param("id")`
- Look up the manager record
- If not found: return 404
- Check caller has co_owner+ access to the manager's property via `getUserPropertyRole(userId, record.propertyId)`
- **Prevent changing the original owner's role:** If the target record has `role: "owner"`, return 403 `{ error: "Cannot change the property owner's role" }`
- Update `role` on the record
- **D-11 notification:** If the manager has a userId, look up their email and send notification via `queueEmail`:

  - Body: "Your role for {propertyName} has been changed to {newRole}."
- Return `{ message: "Role updated", data: updatedRecord }`

**DELETE `/:id` -- Remove a manager from a property:**

  - Subject: "Your access has been revoked on Rentular"
  - Body: "Your access to {propertyName} has been revoked."
- Delete the record
- Return `{ message: "Manager removed" }`
