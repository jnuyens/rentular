**1. Sidebar role filtering** (`apps/web/app/(dashboard)/layout.tsx`):

Per D-09, filter navigation items based on the user's most permissive role across all accessible properties. The sidebar is a server component, so fetch the user's roles server-side.

Add a fetch call to the API in the server component to get the user's accessible properties with roles. Use `GET /api/v1/property-managers/my-properties` endpoint.

Since the layout is a server component, use `fetch` with the session cookie forwarded. Alternatively, since accessing the API from a server component requires forwarding cookies, use a simpler approach: call the properties endpoint that already includes `userRole`.

Practical approach: Add a server-side fetch to `${process.env.NEXT_PUBLIC_API_URL || "http://localhost:4000"}/api/v1/properties` with the session cookie forwarded from the request headers. Extract the highest `userRole` across all returned properties.

```typescript
import { cookies, headers } from "next/headers";

// Inside DashboardLayout:
let highestRole = "viewer";
try {
  const cookieStore = await cookies();
  const cookieHeader = cookieStore.toString();
  const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL || "http://localhost:4000"}/api/v1/properties`, {
    headers: { Cookie: cookieHeader },
    cache: "no-store",
  });
  if (res.ok) {
    const json = await res.json();
    const ROLE_PRIORITY: Record<string, number> = {
      owner: 5, co_owner: 4, manager: 3, accountant: 2, viewer: 1,
    };
    for (const prop of json.data || []) {
      if ((ROLE_PRIORITY[prop.userRole] || 0) > (ROLE_PRIORITY[highestRole] || 0)) {
        highestRole = prop.userRole;
      }
    }
  }
} catch { /* Default to viewer if API unreachable */ }
```
