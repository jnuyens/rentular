# Quick Task 261104-qk9: Automatic reminders for the shortfall of partly paid months

## Goal

Owner decision (2026-11-04): partly paid months get the same automatic reminders as unpaid ones, for exactly the missing amount. Today the overdue flow in paymentCheckWorker only iterates PENDING payment rows, so a month whose only row is paid but short (Carnotstraat 65 b102: paid 900 of 925 for November 2026) is never reminded. Also fix what the first two real shortfall reminders (sent manually on 2026-11-04) showed wrong in the reminder texts.

## Context

- Exact settlement helpers: apps/api/src/services/monthReceived.ts (monthSettlement, loadMonthStatus, receivedForMonth, rentForDate). Coverage is exact to the cent; never reintroduce tolerances.
- Overdue flow: paymentCheckWorker.ts Phase A iterates pending, non-ignored, non-deposit rows with dueDate < today; periodSettlement(...) skips settled months and uses the shortfall as the reminder amount for partly paid months.
- Manual reminders: services/manualReminder.ts (already asks for the shortfall).
- Real messages sent on 2026-11-04 (communications table): NL "uw huurbetaling van €70.00 voor Tervuursestraat 97 leuven verschuldigd was op 2026-11-02." and FR "votre paiement de loyer de €25.00 pour Carnotstraat 65 b102 Antwerpen etait du le 2026-11-04." Problems: ISO dates instead of Belgian dd/mm/yyyy, amounts not in Belgian format (€ 70,00 / 70,00 € style per locale), French without accents, and nothing tells the tenant this is the remaining part of the rent (after a partial payment / after the indexation).

## Tasks

### Task 1: Remainder rows for partly paid months (worker sweep)

- Add a sweep at the start of Phase A (before selecting overdue rows): for every active lease, for the current month and the previous 6 calendar months (month >= lease start, lease not ended before that month, due date < today... use due <= today minus nothing: a month is eligible once its due date has passed, i.e. due < today, same as the overdue query), compute the exact settlement. When 0 < received < expected AND the lease has no pending/processing non-ignored non-deposit row for that month, insert ONE pending row: amount = shortfall, rentAmount = shortfall, chargesAmount 0, dueDate = the month's due date, method = lease default (gocardless or bank_transfer as elsewhere), notes = "remaining amount after partial payment" (a stable marker, export it as a constant, e.g. REMAINDER_NOTE, and make isDepositNote-style detection possible). Idempotent: never a second remainder row for the same lease+month; if the shortfall changed (e.g. another partial payment arrived) update the existing pending remainder row's amount instead.
- The settlement must not double count: a pending remainder row is pending, so received stays the paid sum. Verify the dashboard (payments.ts /dashboard, prior-month loop deduped by lease+month) still reports the month once with the right shortfall, and that the Tervuursestraat case (pending 810 row + paid 740) does NOT get an extra remainder row (it already has a pending row).
- When the tenant then pays exactly the shortfall, the existing matchers (exact amount, paymentPicker) close the remainder row; the month becomes settled. Add a test.
- If a pending remainder row's month becomes settled by other means (allocation, a bigger payment), the existing isPeriodSettled check already skips reminders; additionally mark such a stale remainder row cancelled in the sweep so it does not linger.
- Unit tests for the sweep decision (pure function: inputs lease, month rows, settlement -> action none/insert/update/cancel), including both prod fixtures (Carnotstraat: insert 25; Tervuursestraat: none).
- Reminder history: the remainder row is a new payment id, so the friendly/formal/final ladder starts on it. Carnotstraat already got a manual friendly reminder on 2026-11-04 attached to its paid row 27ccf731-f0a3-4635-a7cf-2cb2edca1c7e: when the sweep creates the remainder row for a month, copy existing payment_reminders of that month's paid rows to count as sent for the new row (or make the ladder look at reminders of all rows of the same lease+month), so the tenant does not get the friendly reminder twice. Pick the simplest correct option and test it.
