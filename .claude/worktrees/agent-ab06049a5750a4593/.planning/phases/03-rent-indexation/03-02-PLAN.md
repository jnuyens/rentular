**Endpoint 1: GET /health-index** (IDX-01 exposure)
- Call `getLatestHealthIndex()` and `isHealthIndexStale()`
- Return `{ currentIndex: Number(latest.value), month: latest.month, year: latest.year, source: "Statbel", lastUpdated: latest.fetchedAt, isStale: stale }`
- If no data: return `{ currentIndex: 0, month: "", year: "", source: "Statbel", lastUpdated: null, isStale: true }`

**Endpoint 2: GET /health-index/history** (IDX-01 exposure)
- Parse `from` and `to` query params (YYYY-MM format)
- Query `healthIndexValues` with optional year/month range filters, ordered by year DESC, month DESC
- Return `{ data: rows.map(r => ({ year: r.year, month: r.month, value: Number(r.value), fetchedAt: r.fetchedAt })) }`

**Endpoint 3: GET /calculate/:leaseId** (IDX-02, IDX-03, IDX-04)
- Get `userId` via `getRequiredUserId(c)`
- Fetch lease with ownership check: `leases` where `id = leaseId AND ownerId = userId`, return 404 if not found
- Check `lease.indexationEnabled` -- if false, return 400 "Indexation is not enabled for this lease"
- Fetch property via `lease.propertyId` from `properties` table for EPC data
- Parse `lease.indexationBaseMonth` (YYYY-MM format) to get base year and base month
- Fetch base health index: `getHealthIndexValue(baseYear, baseMonth)` -- if null, return 400 "Base health index not available for {baseMonth}"
- Calculate the "current" index month: the month before the lease anniversary month. Anniversary month = same month as lease start. Current index month = anniversary month - 1. Use `getHealthIndexValue(currentYear, currentMonth)` -- if null, return 400 "Current health index not available"
- Per D-06: use `lease.monthlyRent` (the ORIGINAL base rent from lease signing) and `lease.indexationBaseIndex` as the base index. The `indexationBaseIndex` field stores the resolved base index value.
- Calculate unrestricted new rent: `calculateIndexedRent(Number(lease.monthlyRent), Number(lease.indexationBaseIndex), Number(currentIndexValue))`
- Apply EPC restrictions based on `lease.region`:
  - **brussels**: call existing `applyBrusselsEpcRestriction(baseRent, unrestrictedNewRent, property.epcLabel)`
  - **flanders**: call existing `applyFlandersEpcRestriction(...)` -- for freeze period indices, fetch Sep 2022 and Sep 2023 values via `getHealthIndexValue("2022", "09")` and `getHealthIndexValue("2023", "09")`
  - **wallonia**: no EPC restrictions, use unrestricted rent
- Calculate effective date: next lease anniversary (lease startDate's month/day in current or next year)
- Return JSON with: leaseId, baseRent, baseIndex, currentIndex, newRent (EPC-restricted), unrestrictedNewRent, difference, effectiveDate, region, epcLabel, epcIndexationFactor, epcRestricted, correctionApplied, formula, formulaNote (per D-15: no mention of previous overrides)

**Endpoint 4: GET /upcoming** (IDX-04 related)
- Get `userId` via `getRequiredUserId(c)`
- Parse `days` query param (default 30)
- Query active leases where `ownerId = userId AND indexationEnabled = true AND status = 'active'`
- For each lease, calculate the next anniversary date. If it falls within the next `days` days, include it.
- For each upcoming lease, run the same calculation logic as /calculate (fetch health indices, apply EPC) but simplified -- return an array of: `{ leaseId, propertyName, tenantName, currentRent, estimatedNewRent, anniversaryDate, region, epcRestricted }`
- Join with properties for `name`, join leaseTenants + tenants for primary tenant name
- Return `{ data: [...], period: "next {days} days" }`

**Endpoint 5: POST /preview/:leaseId** (IDX-04, IDX-05, IDX-06)
- Get `userId` via `getRequiredUserId(c)`
- Run the same calculation as /calculate to get `calculatedNewRent` (the EPC-restricted maximum)
- Per D-08: if `overrideNewRent` is provided and exceeds `calculatedNewRent`, return 400 "Override rent cannot exceed the indexed rent of {calculatedNewRent}"
- `finalNewRent = overrideNewRent && overrideNewRent <= calculatedNewRent ? overrideNewRent : calculatedNewRent`
- Fetch primary tenant (via leaseTenants where isPrimary=true) for language and name
- Fetch owner (users table) for name
- Fetch property for name
- Per D-13: If no custom subject/body provided, generate defaults using `generateDefaultIndexationEmail()` with tenant language, region, all amounts, and owner name
- Render the template with `renderTemplate()` to show the landlord a preview with real values substituted
- Return `{ leaseId, calculatedNewRent, finalNewRent, isOverride: finalNewRent < calculatedNewRent, subject, body (rendered preview), rawSubject, rawBody (with placeholders for further editing) }`

**Endpoint 6: POST /apply/:leaseId** (IDX-05, IDX-06, IDX-07, IDX-08)
- Get `userId` via `getRequiredUserId(c)`
- Run calculation to get `calculatedNewRent`
- Validate `newRent <= calculatedNewRent` per D-08 (EPC hard cap) -- return 400 if exceeded
- Per D-09: store only the applied rent in indexationRecords
- **Create indexation record:**
  ```
  await db.insert(indexationRecords).values({
    id: crypto.randomUUID(),
    leaseId,
    effectiveDate: calculatedEffectiveDate,
    previousRent: String(lease.currentMonthlyRent || lease.monthlyRent),
    newRent: String(newRent),
    baseIndex: String(lease.indexationBaseIndex),
    currentIndex: currentIndexValue,
    status: sendNotification ? "notified" : "applied",
    notificationSentAt: sendNotification ? new Date() : null,
  });
  ```
- **Update lease** per D-07 (overrides do not affect future calculations -- monthlyRent stays as original):
  ```
  await db.update(leases)
    .set({
      currentMonthlyRent: String(newRent),
      lastIndexationDate: calculatedEffectiveDate,
      updatedAt: new Date(),
    })
    .where(eq(leases.id, leaseId));
  ```
  Note: `leases.monthlyRent` (the base rent) is NEVER modified -- only `currentMonthlyRent` changes.
- **Send notification email** per D-14 (immediately, no delay):
  If `sendNotification` is true:
  - Fetch primary tenant email and language
  - Render the provided `subject` and `body` using `renderTemplate()` with all variables (tenantName, propertyName, currentRent, newRent, baseIndex, currentIndex, effectiveDate, ownerName, legalReference, overrideNote)
  - Call `queueEmail({ to: tenant.email, subject: renderedSubject, body: renderedBody })`
  - If tenant has no email, skip notification but still apply (log warning)
- Return `{ message: "Indexation applied", leaseId, newRent, previousRent, effectiveDate, notificationSent: boolean, indexationRecordId }`

**Shared helper function to avoid duplication between calculate/preview/apply:**
Create an internal helper `async function calculateLeaseIndexation(leaseId: string, userId: string)` that:

- Computes unrestricted and restricted new rents
- Returns all calculation results or throws with descriptive error
- Called by /calculate, /preview, and /apply endpoints
